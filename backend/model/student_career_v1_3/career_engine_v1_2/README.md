# AI Career Engine v1.2 — 개발용 데이터·계산 패키지

작성일: 2026-10-03 (한국시간)

## 이번에 완성한 범위

50개 직군 × 14개 업무 = 700개 업무 레코드, junior/mid/senior 150개 분포, 18개 질문 매핑, JSON/SQLite 데이터, Python 계산 엔진, 대표 7개 직군 예제, 12개 검증 테스트.
외부 라이브러리 없이 Python 3 표준 라이브러리로 실행 가능하다.

**상태: 실행 가능한 초기 설계 데이터. 실증 검증된 직업 예측 모델은 아니다.** 이전 대화에서 제시된 2032.8, 2039+ 등의 날짜 및 직군 점수는 이 엔진의 실측 결과가 아니다. 이번 파일의 결과와 구분해야 한다.

## 파일 안내

| 파일 | 내용 |
|---|---|
| occupations.json | 50개 서비스용 직군, 공식 분류코드는 미매핑 |
| tasks.json | 700개 업무, 능력요건·현실장벽·근거상태 |
| career_profiles.json | 150개 합계 1인 임시 업무분포 |
| seed.sqlite | 직군·업무·경력분포 FK 연결 데이터베이스 |
| questions.json | 질문→필드→계산 또는 수집 전용 구분 |
| config.json | 초기 능력·세 시나리오·기준값 |
| engine.py | 8개 지표, 종합지표, 연도별 결과, 업무별 설명 |
| validate.py / validation_report.json | 테스트 및 7개 대표 직군 계산 결과 |
| example_profile.json / example_result.json | 입력·출력 예시 |
| sources.json | 확인한 연구 출처, 적용 범위 |
| DEVELOPMENT.md | 개발 인수 기준과 후속 보정 작업 |
| build.py / questions_build.py | 데이터 생성 원본 |

## 실행

```bash
python3 validate.py
python3 engine.py example_profile.json --output my_result.json
```
seed.sqlite 재생성 전 기존 파일을 제거하거나 별도 디렉터리에서 build.py를 실행한다. 최초 데이터는 이미 포함되어 있으므로 재생성할 필요 없다.

## 입력

occupation_id 필수. 실제 task_weights는 task ID→0–1 값이며 합계 1. 해당하지 않는 업무는 0 또는 생략. 실제 입력이 없으면 career_level 임시 분포 사용. 연차나 나이를 직접 위험 점수로 쓰지 않는다.

ai_maturity: none / individual / official / integrated / agent.
개인 능력: ai_fluency, domain_expertise, problem_definition, learning_velocity, cross_functional, decision_authority 각각 0–100. 엔진 누락 기본값 50은 개발용 중립값이므로 제품 설문에서는 필수 응답으로 받는다.
market_demand: 선택적 -100–100 시나리오 입력. 없으면 null. 관측 수요를 확보했다는 뜻이 아니다.
회사규모·산업·고객관계·리더십 등 일부 질문은 수집 전용이며 현재 수식에 들어가지 않는다. questions.json에 명시되어 있다.

## 계산 규칙

요구 능력과 AI 능력의 비율을 1로 제한하고, 중요한 능력 중 최저 충족도와 평균 충족도를 절반씩 합쳐 CapabilityMatch를 만든다. Exposure는 이 충족도 점수이다. Automation은 디지털성·표준화·검증가능성·물리성·도입수준·인간장벽을 추가 적용한 업무 비중 가중 지수이다. 100점 척도의 지수이며 자동화 확률이나 고용감소율이 아니다.

인간장벽은 신뢰·책임·규제·현장성의 최댓값을 사용한다. 여러 장벽을 곱해 필요 이상으로 작은 값이 되는 문제를 피하기 위한 초기 설계 선택이다. 책임을 AI 능력 벡터에 넣지 않는다.

Augmentation은 능력 충족도와 개인 AI 활용도를 반영한다. 개인 AI 활용도가 높아져도 Exposure나 Automation 자체는 늘지 않는다. 역할 압축·확장은 업무별 crossover 설계값에 연결되나, 실제 인접 직군 네트워크는 아직 없다.

Task Migration은 5개 자기보고 항목 평균으로 구현했다. 복잡한 수식보다 검토 가능한 기준을 우선한 임시 설계다. Career Disruption은 자동화·압축 압력에 증강·이동능력·선택적 수요의 완화효과를 곱한다. Career Resilience는 그 보수이다. 독립 검증된 심리측정 점수가 아니다.

세 시나리오의 연간 능력 접근률은 .025/.055/.09이며 연구에서 추정한 값이 아니다. 물리 능력에는 .4배를 적용한다. METR의 시간지평 두 배를 자동화율 두 배로 환산하지 않는다.

## 날짜 표시

- Assistance: 증강 지수 60 최초 도달 연도. 생산성 열위의 실증 기준이 아닌 UI용 초기 기준.
- Task Disruption: 자동화 지수 30 최초 도달 연도. 실제 업무 30%가 사라진다는 검증된 의미는 없다.
- Career Transformation: 종합 재편 지수 60 최초 도달 연도.
- 탐색 범위 2026–2040. null은 관측 범위 안에서 미도달이며 영구 안전을 뜻하지 않는다.
- slow/base/fast는 조건부 시나리오이며 통계적 신뢰구간이 아니다. confidence_interval은 null로 유지한다. 월·일 수준 정밀한 날짜는 제공하지 않는다.

## 근거 관리

ILO는 업무 단위 노출 분석과 직무 변형 관점을 뒷받침한다. OECD의 능력 축은 taxonomy의 개념적 참고다. 이 패키지는 OECD 지표의 공식 점수를 재현하지 않는다. 한국 기업 도입률은 모집단·기업규모의 조사값이며 특정 개인의 업무 자동화율이 아니다. 따라서 27.4%, 63.3%를 사용자 프로필에 자동 곱하지 않는다.

700개 레코드의 수치·업무비중·경력분포는 저자 설계값이다. 업무당 독립 조사값을 확보한 것처럼 source_ids를 채우지 않았다. 점수는 9개 템플릿과 명시적 업무 분류 규칙에서 출발하며, 업무별 전문 평가가 필요하다. 불확실성 0–100은 검토 전 전체 가능 범위를 뜻하며 추정 신뢰구간이 아니다.

## 검증 결과와 한계

12개 테스트 통과: 건수·ID·참조·분포 합계, 50개 직군의 점수 범위, 잘못된 입력 거부, AI 활용도·도입 수준·수요 변화의 방향성, 현장직 자동화 제약, 시나리오 방향성, 개인 업무비중 반영, 허위 신뢰구간 차단.

7개 직군 결과는 동일한 가상 개인·조직 조건에서 비교했다. 이는 엔진 sanity check이며 실증 calibration이 아니다. 초기 현장·규제 장벽이 강해 날짜가 미도달로 나오는 경우가 있으며, 원하는 날짜를 만들기 위해 계수를 조정하지 않았다.

생산성 증가→직무 압축→채용수요 변화의 인과관계, 산업수요, 자동화 경제성, 회사 예산·조직정책, 실제 고객소유·리더십 효과는 아직 실증 구현하지 않았다. 데이터셋은 공식 한국직업분류 매핑 완료본도 아니다.
