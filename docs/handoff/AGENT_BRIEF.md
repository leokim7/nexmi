# 개발 에이전트 구현 지시 v1.5

두 그룹을 같은 플랫폼의 별도 진입으로 구현한다. 재직자 ‘내 직업 예상 종료일’과 진로 고민자 ‘진로·직업 적합도 분석’. 후자는 middle/high/university/jobseeker 4단계. 채용공고·기업추천·입사지원·지원이력 기능은 구현하지 않는다.

## P0 — 두 그룹 핵심

- 공통선택 entry. 재직자19화면, 진로25화면을 연결한다. 디자인 토큰·저장권한·리포트 컴포넌트 공유.
- 재직자: 직군/역할→14업무합100%→AI도입→6개능력→검토→3가정전환시점→8지표/업무/전망/근거→What-if→계획→저장/비교/리포트.
- 진로: 학령/준비단계→8관심축→경험/시간/선택능력→후보→직군비교→직군당두체험→성찰→학습경로/준비계획/재계산.
- 실제계산은 model/의 Python 엔진 사용. TypeScript 이식 시 고정예제 parity 테스트 필수. LLM으로 점수·날짜를 생성하지 않는다.
- 재직자 종료일은 career_transformation threshold 연도. null이면 ‘2040년까지 기준 미도달’, 영구안전·2041확정으로 표현하지 않는다. 세가정은 통계신뢰구간이 아니다.
- 진로 적합도는 검증전 탐색지수이며 적성확률이 아니다. unknown=null, 준비수준은순위에반영하지 않음. 가치관은현재수집전용; UI와설명에서미반영을명시한다.
- 저장동의이전 메모리만 사용. 서버계산과 영구저장을 구분. 데이터소유권·삭제·동의·공유범위 필수.

## P1 — 지속방문 핵심

나의변화대시보드, 주간업무적용/체험기록, 다음과제, 목표, 월간리포트, 검증된분야업데이트, 선택알림. 운영로그인·서버스냅샷·명시적알림채널과관리자검토·발행. 새정보·실제변화없으면 결과날짜를 흔들거나 가짜피드를 생성하지 않는다.

## 구현 순서

1. 두 엔진·jobseeker 입력/API·데이터검증과 고정결과 확인.
2. 공통 UI/라우팅, 두 모드의 입력→결과 완성.
3. 업무/직군상세, 비교, What-if, 체험·성찰,계획.
4. 원본스냅샷 저장·기기삭제·리포트·기록대시보드.
5. P1 일지/다음과제/월간변화/콘텐츠검토/선택알림.
6. 모바일360/390,태블릿768,데스크톱1280/1440과키보드·스크린리더 검증.

권장 구조: React TypeScript + Python 계산백엔드 + PostgreSQL. 기존저장소스택 있으면 활용. 특정 라이브러리 버전·클라우드가 확정된 것은 아니다. 엔진의 계수를 UI편의로 변경하지 않는다. 실제 관측 없이는 직군평균·백분위·예측확률을 만들지 않는다.

확정범위와 시안구현차이는 PROTOTYPE_LIMITS.md 참조. 인증·외부알림·AI뉴스수집은 시안에 구현된 기능이 아니므로 운영완료로 보고하지 않는다. 코드·migration·실행가이드·검증·완료/미완료표를 제출한다.
